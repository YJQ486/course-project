### 2. 软件部分（已完成代码 + 验证）
- **片内 RTC 走时**：采用 LSE 32.768kHz，已写好 set/get 封装。 `【待补：实测走时 24h 误差】`

  静止 5s 计 0 步、走路 10s@2Hz 计 19 步（预期约 20 步），逻辑正确。 `【待补：真人佩戴 100 步实测误差】`

## 三、 遇到的技术障碍与解决方案

| 序号 | 技术障碍 | 解决方案 | 状态 |
| :---: | :--- | :--- | :---: |
| 1 | SysTick 软件计时在进入 STOP 低功耗后停摆、时间丢失 | 改用片内 RTC（LSE）走时，RTC 独立后备域，休眠持续走时 | 已解决（方案） |
| 2 | STM32F1 硬件 I2C 外设存在总线死锁缺陷 | OLED 改软件模拟 I2C，MPU6050 保留硬件 I2C1，双总线物理隔离 | 已解决（方案） |
| 3 | 最高优先级任务忙等轮询会饿死其他任务 | Task_Power 改为 500ms 周期 + 事件标志，唤醒即让出 CPU | 已解决（方案） |
| 4 | STOP 模式下编码器旋转（TIM2）无法唤醒 | 唤醒源改用 EXTI：编码器按键 + MPU6050 抬腕中断 | 已解决（方案） |
| 5 | `【待补：联调中遇到的实际问题，如 I2C 时序、编码器抖动、FreeRTOS 栈溢出等】` | `【待补】` | `【待补】` |
