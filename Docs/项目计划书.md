# 《2026嵌入式系统课程设计》项目计划书

**项目名称：** 题目2 - 基于STM32F103C8T6的智能手表设计
**建设目标：** 完成基本要求 + 扩展要求1（编码器菜单）、2（蓝牙上位机）、4（运动计步与数据记录）

## 一、 项目基本信息

* **项目名称：** 基于STM32F103C8T6的智能手表设计
* **选题方向：** 可穿戴设备与嵌入式实时操作系统应用
* **建设目标：** 全面达成大纲基本要求，精准攻克扩展要求1（编码器菜单）、2（蓝牙上位机）、4（运动计步与数据记录）。放弃扩展3（PCB设计），专注于算法与FreeRTOS深度集成。只保留核心模块，加入一键开机电路，最大化提升一验、二验的软硬件系统稳定性。
* **开发周期：** 2026年6月29日 —— 2026年7月10日（最终验收评定）

## 二、 系统总体方案设计

系统采用模块化设计，以学校领用的STM32F103C8T6最小系统板为核心，外围在面包板上互联传感器与通信单元。软件基于FreeRTOS抢占式多任务内核调度，杜绝裸机复杂状态机的低效死等。

1. **交互输入（扩展1）：** 采用EC11旋转编码器。利用STM32定时器硬件正交解码接口（Encoder Mode），实现多级结构体菜单的高效线性翻页、数值增减与按键确认。
2. **无线通信（扩展2）：** 集成JDY-31经典蓝牙模块。通过标准串口（USART2）配置环形缓冲区，实现智能手表与PC端（或手机App）自定义图形化上位机之间的运动数据无线实时同步。
3. **运动计步（扩展4）：** 采用单传感器轻量化方案。直接使用MPU6050六轴加速度计通过硬件I2C1总线高频采样。软件层引入动态阈值与波峰检测滤波算法，滤除日常生活中的杂散抖动，解算出精准步数。利用主控RAM构建链表缓存，实现历史运动数据的本地记录。
4. **显示与时钟电源：** 时间基准采用 STM32F103 **片内 RTC 外设**，复用最小系统板**板载的 32.768kHz 晶振（LSE）** 走时（不引入额外 RTC 芯片，BOM 与预算不变，LSE 缺失时自动回退片内 LSI）。RTC 位于独立后备域，**在 STOP 低功耗模式下仍持续走时**，避免休眠导致时间丢失。显示采用1.3寸OLED屏，为规避 STM32F1 硬件 I2C 总线死锁缺陷并提升稳定性，OLED 采用**软件模拟 I2C（GPIO 位翻转）** 独立渲染多级UI；MPU6050 则保留**硬件 I2C1**，两路总线物理隔离、互不冲突。电源部分采用3.7V锂电池，配合TP4056充电芯片及XC6206稳压管输出3.3V纯净供电，并搭建分立元件设计一键开机电路。

## 三、 FreeRTOS 实时任务规划

针对系统功能，FreeRTOS 内核任务规划如下（任务间采用消息队列与互斥信号量进行通信）：

| 任务名称 | 优先级 | 周期/触发方式 | 任务核心职责（精细对齐扩展要求） |
| :--- | :---: | :---: | :--- |
| **Task_Power** | 最高（4） | 500ms周期+事件标志 | 电源后台监测（周期唤醒比较活动时间戳，非忙等轮询）：超时10s熄屏并进入STOP低功耗模式；唤醒源为 EXTI 外部中断（编码器按键 / MPU6050 抬腕中断），STOP 下编码器旋转不参与唤醒。 |
| **Task_Sensor** | 高（3） | 20ms 周期定时 | 高频采样MPU6050原始数据（硬件I2C1）并执行滤波计步算法，实时更新累计步数并低频落盘至内部Flash（对齐扩展4）。 |
| **Task_UI** | 中（2） | 事件驱动/编码器中断 | 响应EC11编码器硬件正交解码数据流，维护并刷新多级结构体菜单状态机；通过软件I2C刷新OLED、读取RTC渲染时间页（对齐扩展1）。 |
| **Task_Comm** | 低（1） | 数据队列触发 | 打包RTC时间、步数及本地历史记录，通过USART2经蓝牙无线同步至图形化上位机（对齐扩展2）。 |

## 五、 开发计划与时间节点安排

* **阶段一：选题确立与物料筹备（6月29日 - 6月30日）**
  * `【核心节点：6月30日 9:00 提交项目计划书】` 确立智能手表选题并精确对齐扩展要求1、2、4。精选极速发货商铺一站式采购物料。落实大纲一键开机拓扑与片内RTC（LSE）走时方案，收紧BOM预算，准时提交《项目计划书》，确保物料在7月2日前全部到位。
* **阶段二：底层驱动测试与设计建档（7月1日 - 7月2日）**
  * `【核心节点：7月2日 9:00 提交系统设计文档并汇报】` 完成面包板电路基本搭建（包含一键开机控制逻辑）。利用STM32CubeMX配置外设，打通EC11正交解码、OLED和MPU6050底层裸机驱动。撰写系统架构、软件任务流程与硬件连线图，按时提交《系统设计文档》并参与分组汇报。
* **阶段三：系统移植与算法攻坚（7月3日 - 7月6日）**
  * `【核心节点：7月6日 15:00 中期检查】` 移植FreeRTOS实时操作系统。配置片内RTC（LSE 32.768kHz）实现稳定走时（STOP模式下不丢时间）。重点攻坚基于MPU6050的动态计步滤波算法、历史数据RAM缓存与内部Flash持久化逻辑和多级结构体菜单交互逻辑。核对所有到货物料，录制阶段性成果演示视频，提交《中期检查报告》接受现场节点检查。
* **阶段四：全功能联调与上位机交付（7月7日 - 7月8日）**
  * `【关键攻坚节点：全力备战第一次系统验收】` 联调FreeRTOS任务架构（OLED走软件I2C、MPU6050走硬件I2C1，两路总线物理隔离，跨任务共享数据由队列+互斥锁保护）。调通蓝牙模块串口异步发包，使用Python快速搭建并交付美观的图形化蓝牙上位机，彻底调通运动数据与RTC时间的双向无线同步。整合10s无操作自动休眠（STOP模式）与EXTI（按键/抬腕）唤醒逻辑。
* **阶段五：系统功能验收与结题报告（7月9日 - 7月10日及后续）**
  * `【核心节点：7月9日 9:00 一验 / 7月10日 9:00 二验】` 7月9日参与第一次现场验收，向教师重点展示基于片内RTC的高精度走时（含休眠不丢时间）、软件滤波计步、顺滑的旋转编码器多级菜单、低功耗进入与蓝牙上位机实时同步。根据一验意见进行快速迭代优化，于10日参加最终成绩评定。验收通过后一周内，使用规范的 LaTeX 模板独立撰写并提交高水平的个人结题报告。
 
### 🔄 团队协同与应急机制

* **每日同步机制**：每日 18:00 召开 15 分钟小组会议，快速同步各成员进度，及时解决协作中遇到的技术堵点与协作问题。

* **应急补位原则**：若某成员因特殊情况无法按时完成任务，将优先由时间弹性较大的成员进行补位协助，确保各阶段的关键里程碑绝不延期。
* **文档与版本共享**：全面使用在线文档工具与 Git 仓库共享所有设计文档、核心代码及测试数据，确保全组版本实时同步、信息透明。
