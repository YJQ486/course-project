# 真机联调故障排查记录（2026-07-02，2026-07-06 更新）

> 对应三个现场问题：①蓝牙只能收不能发/手机连不上 ②开机偶发卡 TIME 页 ~10s 且不熄屏 ③抬腕唤不醒。
> 本文记录根因分析、代码修复点与上机验证步骤，可直接作为结题报告"调试与问题解决"一节的素材。

---

## 问题一：蓝牙"只能收不能发"、手机连不上

### 根因分析（按可能性排序）

1. **手表大部分时间在熄屏（旧方案为 STOP 休眠），蓝牙对 MCU 完全失联**。
   无操作 10s 即熄屏，旧 STOP 方案下 USART2 无时钟：手表既不推送状态，也收不到命令。
   JDY-31 模块独立供电，休眠期间手机仍能配对/连接模块——于是现象恰好是
   "能连上但收不到手表数据"，像"只能收不能发"。**测蓝牙时你低头摆弄手机
   的那几秒，手表已经睡了。**
   （新方案改为仅关 OLED、MCU 全速运行，蓝牙在熄屏期间正常工作，此问题自然解决。）
2. **UART 接收链路存在两个"永久断链"缺陷**（修复前）：
   - 收发共用 HAL 锁：中断里重挂 `HAL_UART_Receive_IT` 若撞上任务里的
     `HAL_UART_Transmit` 持锁，返回 BUSY，接收从此不再重挂；
   - 过载/帧错误（ORE/FE）后 HAL 撤销接收且不自动恢复。
3. **手机侧使用问题（非固件）**：JDY-31 是经典蓝牙 SPP 透传模块——
   - **iPhone 不支持 SPP，永远连不上**，必须用 Android；
   - Android 系统设置里配对（PIN 一般 `1234`）后显示"未连接"是**正常的**，
     必须打开串口 App（如 *Serial Bluetooth Terminal*）主动建立 SPP 连接；
   - PC 端配对后会生成 COM 口，用 `Host/watch_gui.py` 选 9600 连接。

### 代码修复

- UART 每收到一个字节就 `mark_activity()`：蓝牙会话进行中保持亮屏（`app_tasks.c`）。
- 新增 `HAL_UART_ErrorCallback`：清 ORE 并重挂接收。
- `Task_Comm` 循环里加 RX 看门狗：发现 `RxState==READY`（接收断链）就重挂。
- RX 看门狗等待从 1000ms 缩短到 100ms：TX 持锁导致 RX 断链后最多 100ms 即恢复，
  对 9600 波特率文本协议最多丢约 12 字节（协议解析器丢弃不完整行即可）。

### 上机验证步骤

1. 烧录后**保持手表亮屏**（转一下编码器），Android 串口 App 连接 JDY-31：
   应每秒收到一行 `T:hh:mm:ss S:total/today A:ax,ay,az`。
2. App 发送 `SET 12 34 56`（结尾加换行），表盘时间应立即变为 12:34:56。
3. 连续收发 1 分钟不断流 → RX 看门狗与错误恢复生效。
4. **熄屏后蓝牙仍可收发**（新方案 MCU 全速运行，UART 始终有时钟）。
5. 若第 1 步收不到任何数据：用 USB-TTL 直接接 PA2/GND 看有无输出，
   区分"固件没发"（查任务/供电）与"模块没转发"（查 PA2→模块 RXD 接线、共地）。
6. 手机连不上模块：确认用的是 Android；模块 LED 慢闪=已连接、快闪=待连接；
   3.3V 供电电流是否足（蓝牙广播有 30~80mA 脉冲，面包板杜邦线压降大时模块会复位）。

## 问题二：开机偶发卡 TIME 页 ~10s、不响应、不熄屏

### 根因分析

1. **"不熄屏"的确定根因**：MPU6050 运动中断（PA4）每次触发都刷新活动时间。
   佩戴/手持状态下手一直在微动，中断以采样率级别反复触发 → 空闲计时永远
   清零 → 永不熄屏。
2. **"卡死"的两个嫌疑**：
   - PA4 原配置为 `NOPULL` 浮空 + 上升沿中断：接线松动/干扰时引脚悬空，
     EXTI 中断风暴可把 CPU 全部吃掉，所有任务饿死（界面卡住、按键无响应），
     且每次风暴中断都刷活动时间（又对上"不熄屏"）；"有时"发生与接触状态相关。
   - Task_Sensor（优先级 3）> Task_UI（2）：F1 硬件 I2C 异常时 HAL 每次调用
     空转 ~25ms 等 BUSY 超时，且 `vTaskDelayUntil` 追赶式立即重试 → UI 饿死。

### 代码修复

- 运动中断不再无条件 `mark_activity`，只在**熄屏时**才调用（亮屏时只计数，
  避免佩戴微动反复刷新活动时间导致永不熄屏；熄屏时运动即唤醒，符合抬腕看表场景）。
- PA4 改内部**下拉**（`main.c` + `.ioc` 已同步），杜绝浮空中断风暴。
- Task_Sensor 连续 5 次 I2C 失败后退避 200ms 并重置节拍基准，UI 不再被饿死。
- 熄屏时 Task_UI 跳过渲染（OLED 已关，软件 I2C 写显存无意义），省 CPU 与功耗。

### 上机验证步骤

1. 开机后放桌上不动：10s 应准时熄屏；拿在手里轻微晃动：同样 10s 熄屏
   （修复前会一直亮）。
2. 故意拔掉 MPU 的 INT 线再开机：系统应正常运行、正常熄屏（只是抬腕失效）。
3. 拔掉 MPU 的 SDA 线开机：界面允许数据不刷新，但编码器翻页必须仍然流畅。

## 问题三：抬腕唤不醒（只能按键唤醒）——三轮排查

> **第一判据**：按键能唤醒，说明 EXTI 唤醒链路本身没问题，
> 坏的一定在"MPU6050 到底有没有产生 INT 上升沿"这一上游环节。

### 第一轮（判断有误，真机复测仍唤不醒）

怀疑 DLPF 5Hz 低通 + 运动检测 5Hz 高通叠加把信号滤没，且 INT 处于锁存态未
清除。据此放宽 DLPF、改成 ~50us 非锁存脉冲模式。**结果：动了还是不醒。**

### 第二轮（查数据手册 + 多方验证后定位两个根因）

1. **缺信号通路复位**。MPU6050 运动检测标准配方要求先写
   `SIGNAL_PATH_RESET(0x68)=0x07` 复位加速度信号通路，否则运动检测前置的
   高通滤波器残留旧状态、阈值比较器永不翻转，INT **根本不产生**。此步此前遗漏。
2. **脉冲模式反而不可靠**。第一轮改成的 ~50us 脉冲太短，经面包板杜邦线与引脚
   输入电容后 EXTI 常常抓不到上升沿。应改回**锁存模式**（`INT_PIN_CFG=0x20`）：
   INT 触发后保持高电平直到读 `INT_STATUS(0x3A)` 清除，给 EXTI 稳定的电平+边沿。

### 第三轮（定位真正根因：I2C 总线竞争 + 高通滤波器过激进）

第二轮修复后 INT 能产生了，但抬腕仍然唤不醒。深入分析后发现 **STOP 模式方案
本身存在结构性缺陷**：

1. **I2C 总线竞争（致命根因）**：`Task_Power`（优先级 4）在 `enter_stop_mode()`
   中调用 `MPU6050_ReadIntStatus()` 清除中断标志，但 `Task_Sensor`（优先级 3）
   每 20ms 也在用 I2C 读传感器数据。当 Task_Power 抢占 Task_Sensor 且后者恰好在
   I2C 事务中（~4ms/20ms ≈ 20% 概率），`HAL_I2C_Mem_Read` 返回 `HAL_BUSY`，
   INT_STATUS 未被读取 → **锁存的 INT 线保持高电平** → STOP 中无新上升沿 →
   抬腕不唤醒。`MPU6050_ReadIntStatus()` 的返回值被忽略，调用方无法感知失败。
   按键（下降沿）每次都能产生新边沿，所以按键始终能唤醒。

2. **DHPF 5Hz 过激进**：加速度高通滤波器设为 5Hz，走路（1-3Hz）和抬腕
   （0.5-2Hz）的加速度变化被严重衰减（-14 ~ -20dB），运动检测灵敏度不足。

3. **MOT_THR 注释错误**：阈值寄存器 1 LSB = 4mg（非注释所写的 1mg），
   thr=15 实为 60mg。

### 最终方案：移除 STOP 模式，改为"仅关屏"

**核心思路**：既然 STOP 模式的 I2C 竞争无法在不引入复杂互斥锁（会死锁或优先级
反转）的情况下彻底消除，且"低功耗电源管理"不在课程考核标准中，直接移除 STOP
模式，熄屏只关 OLED、MCU 全速运行。

代码改动（`app_tasks.c`）：

- `enter_stop_mode()` → `enter_idle()`：只调用 `OLED_DisplayOff()` + 置 `s_screen_off=1`。
- `exit_idle()`：`OLED_DisplayOn()` + 清 `s_screen_off` + `mark_activity()`。
- `Task_Power`：熄屏时检测到活动（运动中断/按键/蓝牙刷新了 `g_last_activity_ms`）
  即调用 `exit_idle()` 亮屏。MCU 全速运行，EXTI 始终被 ISR 正常服务。
- `HAL_GPIO_EXTI_Callback`：运动中断在 `s_screen_off==1` 时才 `mark_activity()`，
  亮屏时只计数（避免佩戴微动导致永不熄屏）。
- 移除所有 STOP 相关代码：时钟重配、tick 挂起/恢复、`__disable_irq` 临界区、
  EXTI/NVIC 清挂起、UART 恢复等 ~40 行易错代码。

代码改动（`bsp_mpu6050.c`）：

- DHPF 从 5Hz（0x01）改为 1.25Hz（0x03）：保留约 80% 的 1Hz 运动信号
  （5Hz 仅保留约 20%），运动检测与计步均更灵敏。
- MOT_THR 注释更正为 1 LSB=4mg。

### 上机验证/标定步骤

1. **链路自检**：亮屏切到 SENSOR 页晃动手表，`INT:` 计数应随动作增长。
   - 计数不增长 → 先查 INT→PA4 接线（模块 INT 是否引出、是否接对）；
   - 接线没问题仍不增长 → 把 `REG_CONFIG` 改 `0x00`（260Hz，最激进配方）再试。
2. 计数会增长后，等熄屏，做"翻腕看表"动作：应在 500ms 内亮屏
   （Task_Power 检测周期）。
3. 标定：误唤醒频繁 → `App_Init` 里 `MPU6050_EnableMotionInt(thr,dur)` 的 thr
   调大（每 +1 = +4mg）或 dur 调大；抬腕唤不醒 → thr 调小或 DLPF 改 0x00。

## 附带修复：一键开机自锁（严重，与三问题无关但必须改）

修复前**全工程没有任何代码拉高 PA8(PWR_HOLD)**，且 `MX_GPIO_Init` 把它初始化
为低电平——脱离 ST-Link 供电后，松开电源键系统立即断电，且 LSE 起振等待可达
数秒，必须一直按住。已改为：`main()` 在 `SystemClock_Config` **之前**就把 PA8
配置为输出并拉高（`.ioc` 中 PA8 初始电平同步改为 High）。

验证：电池供电，短按电源键约 1s 松手，系统应保持运行。
