# 真机联调故障排查记录（2026-07-02）

> 对应三个现场问题：①蓝牙只能收不能发/手机连不上 ②开机偶发卡 TIME 页 ~10s 且不熄屏 ③STOP 后抬腕唤不醒。
> 本文记录根因分析、代码修复点与上机验证步骤，可直接作为结题报告"调试与问题解决"一节的素材。

---

## 问题一：蓝牙"只能收不能发"、手机连不上

### 根因分析（按可能性排序）

1. **手表大部分时间在 STOP 休眠，蓝牙对 MCU 完全失联**。
   无操作 10s 即进 STOP，STOP 下 USART2 无时钟：手表既不推送状态，也收不到命令。
   JDY-31 模块独立供电，休眠期间手机仍能配对/连接模块——于是现象恰好是
   "能连上但收不到手表数据"，像"只能收不能发"。**测蓝牙时你低头摆弄手机
   的那几秒，手表已经睡了。**
2. **UART 接收链路存在两个"永久断链"缺陷**（修复前）：
   - 收发共用 HAL 锁：中断里重挂 `HAL_UART_Receive_IT` 若撞上任务里的
     `HAL_UART_Transmit` 持锁，返回 BUSY，接收从此不再重挂；
   - 过载/帧错误（ORE/FE）后 HAL 撤销接收且不自动恢复（STOP 唤醒瞬间残留
     半个字节就会触发）。
3. **手机侧使用问题（非固件）**：JDY-31 是经典蓝牙 SPP 透传模块——
   - **iPhone 不支持 SPP，永远连不上**，必须用 Android；
   - Android 系统设置里配对（PIN 一般 `1234`）后显示"未连接"是**正常的**，
     必须打开串口 App（如 *Serial Bluetooth Terminal*）主动建立 SPP 连接；
   - PC 端配对后会生成 COM 口，用 `Host/watch_gui.py` 选 9600 连接。

### 代码修复

- UART 每收到一个字节就 `mark_activity()`：蓝牙会话进行中手表不休眠（`app_tasks.c`）。
- 新增 `HAL_UART_ErrorCallback`：清 ORE 并重挂接收。
- `Task_Comm` 循环里加 RX 看门狗：发现 `RxState==READY`（接收断链）就重挂。
- STOP 唤醒后 `HAL_UART_AbortReceive` + 重挂，清掉休眠期间的错误状态。

### 上机验证步骤

1. 烧录后**保持手表亮屏**（转一下编码器），Android 串口 App 连接 JDY-31：
   应每秒收到一行 `T:hh:mm:ss S:total/today A:ax,ay,az`。
2. App 发送 `SET 12 34 56`（结尾加换行），表盘时间应立即变为 12:34:56。
3. 连续收发 1 分钟不断流 → RX 看门狗与错误恢复生效。
4. 若第 1 步收不到任何数据：用 USB-TTL 直接接 PA2/GND 看有无输出，
   区分"固件没发"（查任务/供电）与"模块没转发"（查 PA2→模块 RXD 接线、共地）。
5. 手机连不上模块：确认用的是 Android；模块 LED 慢闪=已连接、快闪=待连接；
   3.3V 供电电流是否足（蓝牙广播有 30~80mA 脉冲，面包板杜邦线压降大时模块会复位）。

## 问题二：开机偶发卡 TIME 页 ~10s、不响应、不熄屏

### 根因分析

1. **"不熄屏"的确定根因**：MPU6050 运动中断（PA4）每次触发都刷新活动时间。
   佩戴/手持状态下手一直在微动，中断以采样率级别反复触发 → 空闲计时永远
   清零 → 永不熄屏。
2. **"卡死"的两个嫌疑**：
   - PA4 原配置为 `NOPULL` 浮空 + 上升沿中断：接线松动/干扰时引脚悬空，
     EXTI 中断风暴可把 CPU 全部吃掉，所有任务饿死（界面卡住、按键无响应），
     且每次风暴中断都刷活动时间（又对上"不熄屏"）；"有时"发生与接触状态相关。
   - Task_Sensor（优先级 3）> Task_UI（2）：F1 硬件 I2C 异常时 HAL 每次调用
     空转 ~25ms 等 BUSY 超时，且 `vTaskDelayUntil` 追赶式立即重试 → UI 饿死。
3. 次要：进 STOP 的"清挂起→WFI"原本不是原子操作，SysTick 挤进来会让 WFI
   穿透，表现为"该熄屏时屏又亮回来"。

### 代码修复

- 运动中断不再 `mark_activity`，只累加计数 `g_mpu_int_count`（熄屏计时只由
  按键/编码器/蓝牙数据刷新；抬腕唤醒不受影响，唤醒后由 `enter_stop_mode`
  尾部统一给亮屏时间）。
- PA4 改内部**下拉**（`main.c` + `.ioc` 已同步），杜绝浮空中断风暴。
- Task_Sensor 连续 5 次 I2C 失败后退避 200ms 并重置节拍基准，UI 不再被饿死。
- STOP 进入序列加 `__disable_irq()` 临界区并清 SysTick/PendSV 挂起位。

### 上机验证步骤

1. 开机后放桌上不动：10s 应准时熄屏；拿在手里轻微晃动：同样 10s 熄屏
   （修复前会一直亮）。
2. 故意拔掉 MPU 的 INT 线再开机：系统应正常运行、正常熄屏（只是抬腕失效）。
3. 拔掉 MPU 的 SDA 线开机：界面允许数据不刷新，但编码器翻页必须仍然流畅。

## 问题三：STOP 后抬腕唤不醒（只能按键唤醒）

### 根因分析

**MPU6050 数字低通(DLPF)与运动检测高通(HPF)把信号滤没了。**
`MPU6050_Init` 为计步把 DLPF 配成 5Hz（`CONFIG=0x06`），而运动检测又固定
经过 5Hz 高通——两者叠加后通带≈0，任何抬腕/晃动都到不了阈值比较器，
INT 引脚从不输出脉冲。按键能唤醒证明 EXTI/STOP 链路本身是好的，
坏的就是"MPU 不出中断"这一环。

### 代码修复

- `MPU6050_EnableMotionInt` 里把 DLPF 改为 44Hz（`CONFIG=0x03`）：中断可以
  触发，计步靠软件 8 点滑动平均平滑，不依赖硬件 5Hz 低通。
- 运动阈值从 20 降到 10，配合现场标定。
- SENSOR 页底部新增 `INT:n` 计数：晃动模块数字应增长，这是抬腕链路的
  自检窗口。

### 上机验证/标定步骤

1. 亮屏状态切到 SENSOR 页，晃动手表：`INT:` 计数应随动作增长。
   - 不增长 → 查 INT→PA4 接线；仍不增长 → 把 `bsp_mpu6050.c` 中
     `REG_CONFIG` 写 `0x00`（260Hz，标准运动中断配方）再试。
2. 等待熄屏进 STOP 后，快速抬腕/翻腕：应亮屏。慢速平移不会触发（5Hz 高通
   特性），演示时用"翻腕看表"动作。
3. 标定：误唤醒频繁 → `App_Init` 中 `MPU6050_EnableMotionInt(thr,1)` 的 thr
   调大（每 +1 约 +2mg）；抬腕唤不醒 → thr 调小或 DLPF 改 0x00。

## 附带修复：一键开机自锁（严重，与三问题无关但必须改）

修复前**全工程没有任何代码拉高 PA8(PWR_HOLD)**，且 `MX_GPIO_Init` 把它初始化
为低电平——脱离 ST-Link 供电后，松开电源键系统立即断电，且 LSE 起振等待可达
数秒，必须一直按住。已改为：`main()` 在 `SystemClock_Config` **之前**就把 PA8
配置为输出并拉高（`.ioc` 中 PA8 初始电平同步改为 High）。

验证：电池供电，短按电源键约 1s 松手，系统应保持运行。
